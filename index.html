What’s in the menu

Each one is a single file with a one-line description. Run any of them on its own, or use the menu above and choose by number.

How it works

The launcher is a single file, and you can read it before you run it.

  1. It downloadsinit.sh pulls the repo into a temporary folder.
  2. It finds scriptsEvery .sh file, in any folder, at any depth, except itself.
  3. It groups by categoryA script's folder is its category — nested folders keep their full path, like cybersecurity/recon. Folders with no scripts never show up. Nothing is hardcoded, so categories appear and disappear on their own.
  4. It shows categories firstPick a category (or “a” for every script together), then pick a script from it. 8 per page by default: press n / p to page, b to go back.
  5. It reads the labelLine 2 of each file becomes “Name - description”.
  6. It runs your pickThe temp folder is deleted when you quit.

Only run scripts you trust. The launcher runs whatever is on the main branch, so skim init.sh first.

Add your own script

Open to everyone through a fork and a pull request. Once it’s merged, it appears in the menu and on this page.

  1. Fork the repo and clone your copy.
  2. Add a .sh file inside the folder for the category it belongs in — an existing one, or a brand-new folder name to create a category on the spot — with the label on line 2. A script at the repo root is filed under general.
  3. Test it with bash your-script.sh.
  4. Push, then open a pull request against main.
# clone your fork
git clone https://github.com/<you>/i.git
cd i
git remote add upstream https://github.com/psvim/i.git
git checkout -b add-my-script

# your-script.sh
#!/usr/bin/env bash
# Name - short description of what it does

echo "Hello from my script"
  • Keep the description short, since it’s what people see in the menu.
  • No secrets, tokens or personal data.
  • Ask for confirmation before anything destructive.
